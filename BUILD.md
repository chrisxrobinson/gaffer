**How to re-run the evidence**
- Unit/integration: `npx pnpm@12.6.0 install && npx pnpm@12.6.0 test`. Covers vitest in `packages/pi-gaffer`: 105 tests, including the S1 checks, a real host `sandboxd` and a mock FPL API.

## Discovered
- [x] Scrolling in the browser: tmux switched xterm.js to the alternate screen, so the browser had 0 lines of scrollback and the wheel did nothing (tmux mouse/copy-mode are deliberately off). Fixed with `terminal-overrides ",*:smcup@:rmcup@"` plus ttyd `scrollback=10000`. Verified: normal buffer, 33 lines of scrollback on resume, wheel scrolls to earlier tool output. Still to confirm by hand: scrollback while a long answer streams.
- [x] 2026-09-28: default model switched to `claude-sonnet-5-5` (released after Pi 0.87.1, so declared in `harness/models.json` until M1.1-1 moved to Pi 1.3.0's catalogue entry; ID, 1M context and 128K output verified with the Models API). A real call through Pi reached the API but was refused with "Your credit balance is too low", so the model-dependent criteria stay blocked until the account has credit.
- [x] ttyd's `--max-clients 1` shows a refused second client only "Press ⏎ to Reconnect", which looks like a failure. Documented in the README troubleshooting section.
- [x] Pi loads each extension with `moduleCache: false`, so extensions can't share module state. They share it through session entries (`gaffer.team`, `gaffer.snapshot`), and the rate limiter is a `globalThis` singleton.
- [x] Pi resolves tool paths and command cwds against the **session** cwd (`ctx.cwd || cwd`), so the harness runs Pi from an empty root-owned `/work` that mirrors the sandbox (ARCHITECTURE §1.4 updated).
- [x] Pi's `bash` operations receive the harness env (`options.env`) and `PI_*` session vars; the sandbox operations drop it, and `exposeSessionEnvironment: false`.
- [x] Pi spreads the extension UI context (`{...ui}`), so a Proxy UI stub loses its methods (test harness uses a plain object).
- [x] ttyd bound to `127.0.0.1` inside a container can't be reached through Docker port publishing, and `0.0.0.0` would expose the TUI to the sandbox network → bind to the default-route (egress) IP (ADR 0005 corrected).
- [x] This Docker Desktop daemon defaults to `seccomp=unconfined`, so the sandbox had `Seccomp: 0` → Moby's v27.3.1 default profile is vendored and set explicitly (ADR 0001 corrected).
- [x] A fork bomb exhausted pids before sandboxd could start its helper threads, and sandboxd as PID 1 left 91 zombies → threads start before the command, `RLIMIT_NPROC` 96 per command, repeated `killpg`, `init: true` (ADR 0001 corrected; ECS needs `initProcessEnabled` in phase 2).
- [x] tmux launches the pane through the account's login shell; `nologin` made it exit immediately → `default-shell /bin/sh` in tmux.conf.
- [x] Compose file secrets keep host file modes; the harness (uid 10002) couldn't read 0600 files on Linux → files 0644 inside a 0700 dir (Docker Desktop hid this).
- [x] `sandboxd` couldn't see an aborted caller of a silent command → socket watcher kills the group on client EOF.
- [x] CDN staleness also affects `entry/{id}/` and picks, not just history/transfers (ADR 0002 corrected).
- [x] A Free Hit week's picks aren't the next GW's squad: the summary reverts to the previous GW's picks and bank (full derivation stays M2).
- [x] Node's strip-only TypeScript rejects parameter properties; the sources use erasable syntax only.
- [x] pnpm 12 fails on unreviewed dependency build scripts; three (`@google/genai`, `esbuild`, `protobufjs`) are explicitly denied in `pnpm-workspace.yaml` (none are needed).
- [x] Faux-provider cost is always $0, so budget tests inject cost via a test-only `message_end` hook; real-provider cost is still unverified (NFR-COST-03).
- [ ] With `PI_OFFLINE=1`, Pi prints "fd/ripgrep not found … skipping download" at startup. Harmless (grep/find tools are not active), but noisy.
- [ ] Still open from TASKS.md: whether Pi passes a tool's `strict` flag to providers (the design doesn't depend on it).

- [x] **`bootstrap-static` has no recent form per GW**, so every snapshot now carries the last six checked GWs' `event/{gw}/live` stats, trimmed (ADR 0002 corrected). A snapshot grows by about 1 MB.
- [x] **open-fpl-solver's `prep_data` calls the live FPL API and reads a CSV from its own `data/` folder**, and the repo is not an installable package (its wheel omits `utils.py` and `paths.py`). `gaffer_lib.plan` builds the solver's input and calls `solve_multi_period_fpl` directly; the image vendors the source. Teams 1–4 only had Triple Captain or fewer chips' worth of work in the live runs, so the four-chip case is not measured live.

## Discovered
- [x] **Pi 0.87.1 has its own `/export`** (the session as HTML), and the TUI handles built-in commands before extension commands, so an extension command called `export` never runs. Gaffer's is `/export-rec`; REQUIREMENTS, ARCHITECTURE, ROADMAP, REPO_LAYOUT and ADR 0005 are corrected. `/share` (a GitHub gist of the session) is also built in; it needs `gh`, which the image doesn't have.
- [x] **Pi validates a tool's arguments before `execute`.** A submission that fails the schema never reaches the tool, so it couldn't be counted or recorded there. The extension counts those through `tool_execution_end` and aborts the run at the third (ADR 0003's "a terminating tool can retry" holds: a thrown error gives the model another turn, a returned result with `terminate: true` ends the run).
- [x] **An exception in a tool's renderer ends the Pi process.** A rejected submission's result has `details: {}` (Pi builds the error result); the renderer assumed a recommendation and threw, and the browser showed "[exited]". Found in the first real TUI run; `submitResultLines` now cannot throw and is tested with the result Pi actually passes.

## Who touches the session store, the sandbox and `/work`, and what the locks do with each
Found by reading every caller of `SessionManager`, `SandboxSession`, `sandboxRun`, `createAgentSession` and `/work` in the repository. The run lock's file is `<GAFFER_SESSIONS_ROOT or the session dir>/.gaffer-run.lock`, so every process with `GAFFER_SESSIONS_ROOT=/sessions` (the image's default) shares one; tests and the container checks that set their own root have their own.

| Process | Sessions | Sandbox and `/work` | With the locks |
|---|---|---|---|
| The terminal (`ttyd → tmux → gaffer-pi`) | `/sessions`; `--continue` | runs | Session lock on open; `--continue` skips a session another process holds; run lock per run (refused with a notice when the App runs). |
| The App's Pi processes (`gaffer-web → gaffer-pi --mode rpc`) | `/sessions`, by path from the bridge | runs | The same code. A process that opens read-only tells the bridge (`gaffer-lock`), which stops it and answers 409. |
| `gaffer-web` itself | reads `/sessions` (list, history), never writes | none | Reads lock files: the rail's "open in the terminal", 409 before spawning for a held session, Go disabled while a run holds the sandbox. |
| The eval runner (`pnpm eval`, `run-eval-m11x.sh`) | SDK sessions in `/sessions/evals/<run>` | runs; scores with `gaffer_lib score` and, for G0, a golden-path rerun to `/work/eval-g0-*.json` outside a run | `GAFFER_UI=headless`, and it **waits** for the run lock (up to 10 min) instead of failing a case. Its session locks are never contended (one file per case). Its scoring calls are outside the run lock, as before. |
| `verify.sh`: `isolation.mjs` | none | probes `/work` | Not locked (as before): verify runs with nobody using the stack. |
| `verify.sh`: `lockdown.mjs`, `commands.mjs` | their own temp roots | none | Their own locks; `gaffer-pi`'s printed launch line. |
| `verify.sh`: `live-snapshot.mjs`, `recommend.mjs` | SDK sessions in temp dirs, root `/sessions` | runs, plus direct reads of `/work/plan.json` | Their runs take the shared run lock. |
| `verify.sh`: `app.mjs` | a scratch root under `/data` | runs | Its own root, so its run lock doesn't meet the terminal's; like the others it assumes an idle stack. |
| `gaffer-eval`, `replay.ts` | read `/sessions` | `gaffer_lib score` / `validate` on stdin; no `/work` writes, no release | None needed (they don't clear `/work`; `gaffer-eval` says so in a comment since M5). |
| `gaffer admin`, `/usage`, the daily cap | read `/sessions` recursively | none | They list `*.jsonl` only: `*.jsonl.lock` and `.gaffer-run.lock` are not sessions. Pi's own `/resume` list and `--continue` filter `.jsonl` the same way. |

**Decided:** refuse rather than queue in the UIs (ADR 0014's notice); wait in headless callers, so the eval suite and verify neither deadlock nor fail when someone is using the terminal (no process ever waits on a lock while holding another). An SDK host's `dispose()` emits no `session_shutdown` (Pi's runtime does that in CLI and RPC modes), so SDK sessions keep their session lock until the process exits and then it is stale by pid; they never cleared `/work` on dispose either. The App's run waits for nothing: the bridge refuses with "A run is in progress in the browser terminal" and the Start screen disables Go while the lock is held.

## Discovered
- [x] **`RpcClient` spawns `node <cliPath> --mode rpc …`**, so the launcher script can't be its `cliPath`. `gaffer-pi` prints Pi's arguments (`GAFFER_PI_PRINT=1`) and the bridge gives them to `RpcClient` with Pi's own CLI, which keeps one launch line for both UIs (the container tests use the same). `RpcClient` has no method for `extension_ui_response`; the bridge writes the cancel to the child's stdin. Not a gap in what S7 recorded: S7 spoke raw JSONL.
- [x] **An SDK session's `dispose()` emits no `session_shutdown`** (only Pi's runtime does). The tests emit it before disposing; the eval runner's locks go stale at exit.
- [x] **`/run`'s `sendUserMessage` is fire-and-forget**, so `prompt "/run …"` answers `handled` before the run starts (as S7 saw). The bridge answers Go only after `agent_start`, or with the warning or error Pi notified instead.
- [x] **A run that `/run` starts skipped the daily cap:** `gaffer-budget`'s `input` check ignores extension-sourced input. `/run` checks the cap itself.
- [x] **The solver call redirects `sys.stdout`** (`contextlib.redirect_stdout`), and `_Recorder.run()`'s MIP-start comprehension rebinds `n` with a walrus, so `n` is a variable name after it. The progress callback counts runs itself; the rebinding is harmless today (nothing reads `n` after it) but a trap.
- [x] **Plans 2–3 and the chip scenarios vary from one run to the next** on the same snapshot (time-limited solves). Old code against itself and old against new differ in the same fields; plan 1 and every deterministic field are identical (`--time-limit 120`, snapshot `2026-27/8/20261018T184447Z-5f065e2a2335`).
- [x] **The sandbox can't read a `mkdtemp` directory** (0700, another uid): `app.mjs` opens its scratch root to 0755 as verify's other scratch dirs are.
- [x] **The harness image has no `ps`**; `app.mjs` counts Pi processes from `/proc`.
- [x] **Bookmaker odds for GW8 weren't published yet** on 2026-10-19 (football-data answered, 0 fixtures priced): the snapshot step says "no bookmaker odds yet" and the Run shows the Dixon-Coles line. The first version only showed it when the source was down.
