# ADR 0015 — Phase 2 host: one Hetzner Cloud server running the same Compose file

**Status:** Proposed (Phase 2 plan, for your review) · **Date:** 2026-10-23 · **Supersedes in part:** [ADR 0006](0006-deployment.md) (its AWS column moves to Phase 3 as a mapping) · **Evidence:** [research 13](../research/13-hosting.md), [research 06](../research/06-deployment.md) · **Requirements:** NFR-PORT-02, NFR-LAT-01, NFR-LAT-03, NFR-SEC-01

## Context
- **AWS is out.** ROADMAP planned Phase 2 on AWS (Fargate, ALB with OIDC, EFS, Secrets Manager). You dropped it for cost, about $140 a month before any egress firewall.
- **What the host must keep:** the brief asks for a small, cheap host that keeps Gaffer host-agnostic (the same images and Compose shape), so a big cloud stays a mapping exercise in Phase 3.
- **What Gaffer depends on:**
  - a real filesystem for Pi's JSONL sessions (ADR 0004);
  - a sandbox with no network and no secrets (ADR 0001), ideally under gVisor;
  - a long-lived WebSocket for ttyd and Server-Sent Events for the App;
  - about a minute of 2-vCPU work per run.

## Options considered
1. **Hetzner Cloud, one server, Docker Compose.** **Chosen.** It keeps everything above unchanged:
   - Docker on Ubuntu 24.04 for arm64 and amd64;
   - gVisor on x86_64 and ARM64;
   - `internal: true` networks;
   - local NVMe disk;
   - €6.49–19.99 a month.

   The catch is that every Cost-Optimized plan (CX and CAX) shows "not available" today. Only CPX (AMD) can be ordered.
2. **Cloudflare Containers behind a Worker or Durable Object.** Rejected:
   - Disk is ephemeral ("a fresh disk from the container image" after sleep).
   - Images must be amd64.
   - Persistence would mean FUSE to R2 or rebuilding the session store on Durable Objects.

   Replacing Pi's file-based `SessionManager` would move Gaffer off "Pi core unchanged, Gaffer as a package". That's a negative result for the thesis on that platform, recorded here. ADR 0011 already found that Durable Objects can't host the sandbox.
3. **Fly.io Machines.** Rejected. It's about $25 a month, and there's no documented way to give the sandbox Machine zero egress.
4. **Oracle Always Free (A1).** Rejected. Oracle may reclaim instances that look idle for 7 days, and Gaffer is idle most of the week.
5. **AWS as ADR 0006 designed it.** Moved to Phase 3, as a documented mapping.

## Decision
- **One Hetzner Cloud server in Germany (NBG1 or FSN1), on Ubuntu 24.04 LTS**, running Gaffer's Compose file with the production overlay (ADRs 0016–0018). The sandbox runs under gVisor (`runsc`) through `docker-compose.gvisor.yml`.
- **Server type, in order of preference, decided at order time by what Hetzner can supply:**
  1. **CAX21** (4 Ampere vCPU / 8 GB / 80 GB, €10.99 a month with IPv4): headroom for the harness while the solver uses 2 vCPU.
  2. **CPX22** (2 AMD vCPU / 4 GB / 80 GB, €19.99), orderable today. The solve takes the whole machine, which is acceptable for one user.
  3. **CAX11** (2 Ampere vCPU / 4 GB, €6.49), if CAX21 is out of stock and the price matters more than headroom.
- **Architecture:** images are built on the host for its own architecture (ADR 0020), so ARM or AMD makes no difference to the repo. The Mac stays arm64.
- **No Hetzner Volume, no Hetzner Backups:** the server's disk holds the volumes (a few hundred MB), and offsite backups are restic's job (ADR 0018).
- **Hetzner's Cloud Firewall allows no inbound traffic at all.** Access is over Tailscale (ADR 0016), whose traffic is outbound from the server.
- **Measured on the host, not assumed:** the golden path's time (NFR-LAT-03, ≤ 60 s) and the eval latency (NFR-LAT-01) on the server type actually bought. If CAX's Ampere cores miss NFR-LAT-03, M2-1 records it, and the fix is a bigger type, not a code change.

## Consequences
- **Monthly cost**, excluding VAT and model spend:

  | | CAX21 | CPX22 | CAX11 |
  |---|---|---|---|
  | Server | €10.99 | €19.99 | €6.49 |
  | Storage Box BX11 (ADR 0018) | €3.20 | €3.20 | €3.20 |
  | Tailscale and healthchecks.io | €0 | €0 | €0 |
  | **Total** | **€14.19** | **€23.19** | **€9.69** |

  The table in research 13 compares the alternatives.
- **NFR-PORT-02 is reworded:** Gaffer runs on any Docker host (macOS, Linux arm64 and amd64), and the Phase 2 host uses the same Compose file and Dockerfiles. ECS Fargate becomes Phase 3's documented mapping.
- **NFR-LAT-02's Fargate cold start no longer applies.** The sandbox is an always-on container, as on the Mac. It's replaced by NFR-LAT-05 (see REQUIREMENTS).
- **One server is a single point of failure.** That's accepted for one user. Recovery is a restore from the offsite backup onto any Docker host, the Mac included (ADR 0018), and it's drilled in M2-2.
- **Ordering the server is yours:** the account, the payment, and picking the type the day you order.
