# ADR 0015 — Phase 2 compute and cost: ECS Fargate on ARM64 in eu-west-2, an always-on harness and sandbox

**Status:** Accepted (2026-10-23, with the ~$183/month budget) · **Date:** 2026-10-23 · **Refines:** [ADR 0006](0006-deployment.md) (Compose mapped 1:1 to ECS Fargate) · **Evidence:** [research 17](../research/17-aws.md), [research 06](../research/06-deployment.md), [research 13](../research/13-hosting.md) (the small-host alternative) · **Requirements:** NFR-PORT-02, NFR-LAT-01, -02, -03, -05, NFR-SEC-01, NFR-COST-01

## Context
- **The decision:** Phase 2 runs on AWS, as ROADMAP and ADR 0006 planned. A single small host (Hetzner with Tailscale, research 13–16) was planned first, at about €14–23 a month. You chose AWS instead, to keep it professional.
- **What ADR 0006 mapped:**
  - the harness as an ECS Fargate service behind an ALB with OIDC;
  - the sandbox as a separate Fargate task per session, through `RunTask`, with a warm pool of 1;
  - EFS, and Secrets Manager.
- **What this ADR settles:**
  - the region and architecture;
  - the task sizes;
  - whether the sandbox runs per session or always on;
  - what it all costs.

## Options considered
1. **Region:** `eu-west-2` (London), close to you (BST) with every service Gaffer needs. **Chosen.** `eu-west-1` (Ireland) is the backup copy's region (ADR 0018).
2. **Architecture:**
   - **ARM64 (Graviton) Fargate.** **Chosen.** It's about 20% cheaper than x86 ($0.03725 against $0.04656 per vCPU-hour), and it matches the Mac's own architecture, so images are built natively with no emulation.
   - x86. Rejected: about $28 a month more, and an emulated or remote build.
3. **The sandbox:**
   - **One always-on Fargate service** (1 task), reached through Cloud Map. **Chosen.**
     - It's the same model as Compose today: one sandbox, the run lock (ADR 0014) serialising runs.
     - No per-run cold start.
     - No new `SandboxProvider` code: `SANDBOX_URL` just points at its Cloud Map name.
   - **Per-session `RunTask` with a warm pool of 1** (ADR 0006). Moved to Phase 3. A warm pool of 1 costs the same as always-on, and per-session sandboxes matter only for concurrent users (they retire the run lock).
   - **Per-run `RunTask` with no warm pool.** Rejected for now. It would save about $60 a month, but adds a 30–60 s cold start to every recommendation and the `ecs` provider code.
4. **The harness:**
   - **One Fargate task with `desiredCount` 1, `minimumHealthyPercent` 0 and `maximumPercent` 100,** so ECS stops the old task before starting a new one and there is never a second writer (ttyd's tmux, ADR 0014's session lock). **Chosen.**
   - Two tasks or blue/green. Rejected: two writers on one session store.

## Decision
- **The region:** `eu-west-2`, across two AZs (the ALB needs two subnets). The harness, sandbox and endpoints run in the first AZ.
- **The task definitions** (Fargate platform 1.4.0+, `LINUX/ARM64`):

  | Service | vCPU / memory | Count | Subnet | Task role |
  |---|---|---|---|---|
  | `gaffer-harness` | 1 / 2 GB | 1 | private | EFS client (read-write on `sessions` and `data`) |
  | `gaffer-sandbox` | 2 / 4 GB | 1 | private | **none** |
  | `gaffer-egress` | 0.25 / 0.5 GB | 1 | public, with a public IPv4 | none |
  | `gaffer-job` | 1 / 2 GB | on schedule (ADR 0019) | private | as the harness |

  - The harness runs ttyd and `gaffer-web`, as today. Its container is non-root, with a read-only root filesystem where the image allows it.
  - The sandbox has the same limits as Compose: non-root, read-only root, no capabilities, a tmpfs `/work`, and `data` read-only. Fargate gives each task its own micro-VM, so gVisor isn't needed there (ADR 0006).
- **Service discovery:** a Cloud Map private namespace, `gaffer.internal` (`sandbox.gaffer.internal`, `egress.gaffer.internal`).
- **The images** are the same Dockerfiles as local Compose, built for `linux/arm64` (NFR-PORT-02).
- **Measured, not assumed:**
  - the tasks' start times (NFR-LAT-02);
  - the sandbox's first-command latency and the golden path's time on Graviton (NFR-LAT-05, NFR-LAT-03 ≤ 60 s);
  - the eval latency (NFR-LAT-01).

  All are measured in M2-1. If the golden path misses 60 s on 2 Graviton vCPU, the fix is a bigger sandbox task, not a code change.

## Consequences
- **Monthly cost** (research 17, list prices, before VAT and data transfer):

  | Line | $/month |
  |---|---|
  | Sandbox (2 vCPU / 4 GB, always on) | 66 |
  | Harness (1 vCPU / 2 GB) | 33 |
  | Four interface endpoints (1 AZ) | 32 |
  | ALB, with about 1 LCU | 25 |
  | Public IPv4 (ALB × 2, proxy × 1) | 11 |
  | Egress proxy | 8 |
  | Everything else (EFS, Backup, Secrets, ECR, Logs, alarms, Route 53, domain, jobs) | 8 |
  | **Total** | **≈ $183**, about $220 with 20% VAT |

  An **AWS Budgets** alert at your chosen figure is part of M2-1 (ADR 0020). M2-2 checks the real bill against this table (the Phase 2 exit allows +20%).
- **The biggest saving is the sandbox's $66, and it's a Phase 3 change:** per-run `RunTask`, trading 30–60 s per recommendation for it. The small host (research 13) stays documented as the low-cost alternative.
- **A deploy or a task failure is a short outage** (about a minute) with one harness task. That's accepted: deploys stay in ADR 0009's windows, and ECS replaces a failed task.
- **NFR-PORT-02 holds as written:** the same images, mapped to ECS Fargate.
