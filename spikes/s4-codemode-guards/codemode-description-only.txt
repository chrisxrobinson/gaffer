Run JavaScript that calls other tools. The input is raw JavaScript (not JSON, no code fence), run as an async function body in a QuickJS sandbox: top-level `await` and `return` work. No Node, file system, network, or timers.
- `await tools.<name>({ ...args })` resolves to a string, or an object if the tool's declaration says so, and rejects with an Error on failure. A tool whose declaration returns an object resolves on failure too when it returned that object; check its fields. Calls still running when the script ends are cancelled.
- Optional first line: `// @options: {"max_output_tokens": 10000, "timeout_ms": 60000}`

Globals:
- `text(value)`, `image(dataUrlOrImageBlock)`, `console.log(...)`, and top-level `return` add output; `exit()` ends the script. With several text items, each starts with a `==> text N/M <==` line, and `console` lines follow the other output in one `<console_output>` block. `image()` also saves the image to a temp file and the result names its path.
- `store(key, value)` and `load(key)` keep JSON values across codemode calls.
- `ALL_TOOLS`, `await searchTools(query, { limit?, namespace? })`, `await describeTool(name)`, `await describeNamespace(name)`: find unlisted tools, such as MCP tools.
- `models`: classifiers and image generation. Read /Users/chrisrobinson/Documents/git/Gaffer/spikes/s4-codemode-guards/node_modules/@earendil-works/pi-coding-agent/docs/codemode.md first.

Nested tools:

### `read`
Read the contents of a file. Supports text files and images (jpg, png, gif, webp, bmp). Images are sent as attachments. For text files, output is truncated to 2000 lines or 50KB (whichever is hit first). Use offset/limit for large files. When you need the full file, continue with offset until complete.

- Use read to examine files instead of cat or sed.

codemode tool declaration:
```ts
declare const tools: { read(args: {
  // Maximum number of lines to read
  limit?: number;
  // Line number to start reading from (1-indexed)
  offset?: number;
  // Path to the file to read (relative or absolute)
  path: string;
}): Promise<string | { data: string; mimeType: string; note: string; type: "image"; }>; };
```

### `bash`
Execute a bash command in the current working directory. Returns stdout and stderr. Output is truncated to last 2000 lines or 50KB (whichever is hit first). If truncated, full output is saved to a temp file. Optionally provide a timeout in seconds.

codemode tool declaration:
```ts
declare const tools: { bash(args: {
  // Shell command to execute
  command: string;
  // Timeout in seconds (optional, no default timeout)
  timeout?: number;
}): Promise<{
  exit_code: number;
  // Full output, when truncated
  full_output_path?: string;
  // Combined stdout and stderr, possibly truncated
  output: string;
  truncated: boolean;
  wall_time_seconds: number;
}>; };
```

### `edit`
Edit a single file using exact text replacement. Every edits[].oldText must match a unique, non-overlapping region of the original file. If two changes affect the same block or nearby lines, merge them into one edit instead of emitting overlapping edits. Do not include large unchanged regions just to connect distant changes.

- Use edit for precise changes (edits[].oldText must match exactly)
- When changing multiple separate locations in one file, use one edit call with multiple entries in edits[] instead of multiple edit calls
- Each edits[].oldText is matched against the original file, not after earlier edits are applied. Do not emit overlapping or nested edits. Merge nearby changes into one edit.
- Keep edits[].oldText as small as possible while still being unique in the file. Do not pad with large unchanged regions.

codemode tool declaration:
```ts
declare const tools: { edit(args: {
  // One or more targeted replacements. Each edit is matched against the original file, not incrementally. Do not include overlapping or nested edits. If two changes touch the same block or nearby lines, merge them into one edit instead.
  edits: Array<{
    // Replacement text for this targeted edit.
    newText: string;
    // Exact text for one targeted replacement. It must be unique in the original file and must not overlap with any other edits[].oldText in the same call.
    oldText: string;
  }>;
  // Path to the file to edit (relative or absolute)
  path: string;
}): Promise<string>; };
```

### `write`
Write content to a file. Creates the file if it doesn't exist, overwrites if it does. Automatically creates parent directories.

- Use write only for new files or complete rewrites.

codemode tool declaration:
```ts
declare const tools: { write(args: {
  // Content to write to the file
  content: string;
  // Path to the file to write (relative or absolute)
  path: string;
}): Promise<string>; };
```

### `fpl_snapshot`
Fetch the user's FPL team and the public FPL data (players, fixtures, GW state, chips), validate it and store an immutable snapshot. Returns a compact summary (squad with selling prices, bank, free transfers, chips, deadline, warnings), derived by gaffer_lib in the sandbox, and the snapshot path, which is readable (read-only) from the sandbox. Per-user data is always fetched fresh; shared data is cached per FPL's update cycle. Never returns raw JSON: read the snapshot files with Python for detail. With include: ["odds"] the snapshot also holds bookmaker odds; the summary ends with the gaffer_lib command that turns the snapshot into a full plan.

codemode tool declaration:
```ts
declare const tools: { fpl_snapshot(args: {
  // Player ids whose per-fixture history (element-summary) to include in the snapshot.
  // @maxItems 20
  element_summaries?: Array<number>;
  // Bypass the shared-data cache. Only when the user asks for the very latest data.
  force_fresh?: boolean;
  // Extra sources. "odds": next-round bookmaker odds and past results from football-data.co.uk, used for team strength. Include it before running the golden path.
  include?: Array<"odds">;
  // FPL team (entry) ID. Defaults to the team set with /team.
  // @integer @minimum 1
  team_id?: number;
}): Promise<string>; };
```

### `submit_recommendation`
Submit the final recommendation for the next GW: transfers, starting XI and bench, captain and vice, chip, a 4-GW plan, a rationale for each decision and a summary. This is the only way a plan becomes final. Gaffer checks it against FPL's rules, the user's preferences and the solver's best plan, using the latest snapshot and the plan file the golden path wrote, and recomputes every number: you supply decisions and words (figures you quote are optional and are corrected). If it is rejected you get the reasons and may resubmit; there are 3 attempts in all. On success the recommendation is saved and shown to the user and the run ends, so make it your last action and say nothing after it.

codemode tool declaration:
```ts
declare const tools: { submit_recommendation(args: {
  // The 4 on the bench. The order is set at submit by the auto-sub simulator.
  // @minItems 4 @maxItems 4
  bench: Array<number>;
  captain: {
    // FPL player (element) id
    // @integer @minimum 1
    id: number;
    // His xP this GW. Optional: recomputed at submit; a gap from your figure is reported.
    xp?: number;
  };
  chip: {
    confidence?: "low" | "medium" | "high";
    play: "wildcard" | "freehit" | "bboost" | "3xc" | null;
    // Why this chip now, or why none. At most 60 words.
    // @maxLength 1440 @pattern ^\s*\S+(?:\s+\S+){0,59}\s*$
    rationale: string;
  };
  // Only to LOWER the computed confidence, with your reason. You can't raise it.
  confidence?: {
    // @maxItems 3
    drivers?: Array<string>;
    overall: "low" | "medium" | "high";
  };
  // The XI's expected points this GW, captain doubled, before hits. Optional: recomputed at submit; a gap from your figure is reported.
  expected_points_gw?: number;
  // The rolling plan: this GW and the next 3, in order (fewer only when the season ends sooner). Entry 0 is this GW; its transfers, chip and captain may be left out.
  // @minItems 1 @maxItems 4
  plan: Array<{
    // FPL player (element) id
    // @integer @minimum 1
    captain?: number;
    chip?: "wildcard" | "freehit" | "bboost" | "3xc" | null;
    // That GW's expected points. Optional: recomputed at submit; a gap from your figure is reported.
    expected_points?: number;
    // @integer @minimum 1 @maximum 38
    gw: number;
    // What this GW is for. At most 60 words.
    // @maxLength 1440 @pattern ^\s*\S+(?:\s+\S+){0,59}\s*$
    note?: string;
    // @maxItems 15
    transfers?: Array<{ in: {
      // FPL player (element) id
      // @integer @minimum 1
      id: number;
    }; out: {
      // FPL player (element) id
      // @integer @minimum 1
      id: number;
    }; }>;
  }>;
  // Path in the sandbox of the plan JSON the golden path wrote for the latest snapshot. Default /work/plan.json.
  // @maxLength 300
  plan_file?: string;
  // The 11 starters after this GW's transfers.
  // @minItems 11 @maxItems 11
  starting_xi: Array<number>;
  // The advice in plain words. At most 120 words.
  // @maxLength 2880 @pattern ^\s*\S+(?:\s+\S+){0,119}\s*$
  summary: string;
  // This GW's transfers (not ones the user has already made). Empty to roll.
  // @maxItems 15
  transfers: Array<{
    confidence?: "low" | "medium" | "high";
    in: {
      // FPL player (element) id
      // @integer @minimum 1
      id: number;
    };
    out: {
      // FPL player (element) id
      // @integer @minimum 1
      id: number;
    };
    // Why this move. At most 60 words.
    // @maxLength 1440 @pattern ^\s*\S+(?:\s+\S+){0,59}\s*$
    rationale: string;
    // xP gained over the 4 GWs shown. Optional: recomputed at submit; a gap from your figure is reported.
    xp_gain_4gw?: number;
    // Decayed xP gained over the 6-GW horizon. Optional: recomputed at submit; a gap from your figure is reported.
    xp_gain_6gw_decayed?: number;
  }>;
  vice_captain: {
    // FPL player (element) id
    // @integer @minimum 1
    id: number;
    // His xP this GW. Optional: recomputed at submit; a gap from your figure is reported.
    xp?: number;
  };
  // Things the user should know that the computed warnings won't say (e.g. a press conference still to come).
  // @maxItems 5
  warnings?: Array<string>;
}): Promise<string>; };
```

### `set_preferences`
Save the user's standing preferences for their team, so they needn't restate them: risk mode, chips to save, players to keep or avoid, and the most hits to take in a GW. Only fields you pass are changed; a list you pass replaces the saved list (pass [] to clear it). Call it when the user states a preference that should last beyond this conversation. Preferences are passed to the golden path with --prefs and enforced when a recommendation is submitted. They are for the team set with /team.

codemode tool declaration:
```ts
declare const tools: { set_preferences(args: {
  // Player ids the user doesn't want bought.
  // @maxItems 50
  avoid?: Array<number>;
  // Player ids the user wants to keep in the squad.
  // @maxItems 15
  keep?: Array<number>;
  // Most hits (−4 each) to take in one GW; null for no limit.
  // @integer @minimum 0 @maximum 15
  max_hits_per_gw?: number | null;
  risk?: "safe" | "balanced" | "aggressive";
  // Chips not to play until the user says otherwise.
  // @maxItems 4
  save_chips?: Array<"wildcard" | "freehit" | "bboost" | "3xc">;
}): Promise<string>; };
```
